## Confirmed bugs

### LIB-01 — supplied asset classification is ignored for a held instrument (P1)

**Impact:** a policy that permits an ETF entry can refuse its risk-reducing exit even when the caller supplies the same valid ETF classification. The error tells the caller to supply information that is already present.

Reproduce without a provider:

1. Create a USD ledger with a synthetic cash deposit and a one-share SPY purchase at a synthetic price.
2. Supply a market snapshot and `instruments: { SPY: { currency: 'USD', contractMultiplier: 1, assetClass: 'etf' } }`.
3. Normalize an intent to sell that one share. Preflight with `allowedInstruments: ['SPY']`, `allowedAssetClasses: ['etf']` and `onUnverifiable: 'deny'`.
4. Observe `orders[0].allowed-asset-class = unverifiable`, a null class and a denied plan. The check should be able to use the supplied classification.

The held-position branch in [the trade resolver](../../packages/portfolio/src/trade/plan.ts) returns `assetClass: null` before considering the caller's instrument description. The position grammar has no asset-class field, so repeating the recommended input cannot resolve the refusal. Preserve the ledger's authoritative currency, multiplier and contract terms when repairing this; make classification resolution explicit.

The actual pilot's close used the exact SPY allowlist without the redundant asset-class filter. The known ETF identity was verified separately; quantity, cash, leverage and notional constraints remained in place. This is an explicitly recorded pilot workaround, not a library fix. The synthetic reproduction confirms the bug independently of staging data.

### LIB-02 — an idempotent ledger retry reports a newly applied event (P2)

**Impact:** accounting is correctly idempotent, but operational telemetry can tell an agent that another event was applied.

Reproduce with the public workflow registry and memory artifact store:

1. Record a synthetic cash event through `totalfinance.portfolio.record_events`.
2. Record the identical event against the returned ledger handle.
3. Observe the same handle and unchanged `eventCount`, but `applied: 1` and the summary "1 event applied" again.

[The operation](../../packages/workflows/src/operations-trade.ts) reports `input.events.length` rather than the number newly folded. Return the actual new-event count and, if useful, a separate requested/duplicate count. Do not change the verified economic deduplication. Actual paper recovery and a separate synthetic reproduction both demonstrate this discrepancy.

### LIB-03 — plan-scoped reconciliation mislabels other plans' valid ledger fills (P2)

**Impact:** restricting reconciliation to one plan can report a financial discrepancy even when every fill is present in both the journal and ledger. The documented input says `planHash` restricts the judgment to one plan's orders.

Reproduce without market data or persistent stores:

1. Create one synthetic account with cash and two normalized fills under the same execution source: plan A buys one share at a synthetic price; plan B sells it.
2. Journal submitted, acknowledged and filled events for both plans, and fold both fills through the public ledger API.
3. Reconcile the complete journal, ledger and fills: observe zero differences and `reconciled: true`.
4. Repeat with `planHash` restricted to B and B's delivered fill. Observe A's valid fill in `ledgerNotJournaled` and `reconciled: false`, alongside a warning that A is not judged.

[The reconciliation join](../../packages/portfolio/src/trade/reconcile.ts) filters journal orders by plan but compares their fill IDs with all ledger fills under the execution source. Make the comparison scope consistent, or separate plan-scoped and source-wide judgments explicitly. Do not hide genuinely orphaned fills in a full-source check. This is a false report, not a duplicated or missing economic event. The actual forward run and a separate entirely synthetic reproduction agree. Full-source reconciliation with all delivered fills was the verified workaround. Unfixed.

### API-01 — option-chain cursor instructions contradict the MCP input schema (P2)

**Impact:** following pagination instructions produces a validation failure.

1. Fetch a bounded `get_option_chain({ symbol: 'SPY', limit: 2 })` page with a continuation cursor.
2. Follow the cursor description: supply the cursor alone, optionally with `limit`.
3. Observe MCP `-32602`: `symbol` is required.
4. Repeat with the same cursor plus `symbol: 'SPY'`: continuation succeeds and retains the original query/snapshot.

The example contains no saved cursor. Fix the published contract so continuation is executable as described. If a symbol remains required for the resource path, teach callers to repeat it and distinguish it from query filters; test that a conflicting symbol cannot silently cross resources. API ownership is external to the compute library.

## Research and paper evidence

Every run reconciled to its ledger. Parameters were set before evaluating results; held-out results were not used to select or tune a rule. No historical publication/revision history, dividend cash-flow dataset or historical cash-yield series was available. Date-only daily rows use the library's explicit date-index convention, not fabricated observed instants.

The available recent history is short and spans one regime. A positive held-out return or a few profitable paper fills does not establish a profitable strategy. The selection-adjusted public SDK diagnostic rejects a confident skill claim. All financial outputs and exact evidence stay in the private research report.

Verified strengths include explicit units, preserved source timestamps/nulls/provisional flags, typed boundary refusals, shared paper/ledger accounting, content-addressed artifacts, reproducible seeded risk calculations, cumulative recovery, same-key submission retry, idempotent ledger effects and reopening filled holdings after an actual MCP server restart. An embedded synthetic retry-storm episode is supporting evidence, separate from the actual staging/paper journey.

The initial frozen install/build and 25 focused trade/recovery/MCP tests passed. Later exploration exercised the built public APIs and transports; this report does not claim a full CI run. No calculation source, public API, generated evidence, release version or provider application source was changed. The external connector, MCP App acceptance and broader milestone remain open.

## Follow-up strategy testing

The follow-up added **136 historical backtests**: 64 intraday runs, 18 longer daily runs and 54 monthly-rule runs. Two exact deterministic replays are additional verification, not extra hypotheses. All 136 runs used the public portfolio engine or its public stepper, with zero ledger reconciliation residual and no rejected orders. Source data and numerical financial results remain private.

The intraday protocol fixed an opening-range breakout, a session-reset RSI pullback, a first-half-hour momentum adaptation and a session-holding benchmark before calculating returns. Three bounded pages were checked for duplicates, ordering, OHLC validity and source availability. Only complete regular sessions were eligible; missing minutes were never imputed. This left four training and four test sessions, with the coverage-based exclusion and its selection risk disclosed. Every signal used a fully available prefix of observations; each session ended flat. Four commission/slippage scenarios and an additional signal-data delay were tested. Every rule lost money on the test sessions after the base costs. This rejects this implementation on this sample; it does not disprove the published momentum literature. The adaptation follows the hypothesis in [Gao et al.](https://profiles.wustl.edu/en/publications/market-intraday-momentum/), with different source coverage, timing and long-only constraints.

Longer history came from a separate, explicitly identified public Yahoo Finance chart response, not from InsiderFinance staging. Its overlapping closes matched staging within rounding precision. The raw snapshot was retained privately; the current session was excluded. The calendar audit initially stopped at an unsupported historical closure, then the research window was restricted to the documented calendar floor **before any financial metric was calculated**. From that floor onward, every supplied session matched the library calendar and no expected sessions were missing. Earlier observed prices served only as indicator warmup in the monthly study.

The original daily rules were carried forward unchanged, with chronological training through 2015 and evaluation from 2016 onward. Two additional, fixed monthly hypotheses used a 200-session moving average and 252-session price momentum. Those follow-ups were registered after earlier results had been examined, so they are exploratory research, not a pristine prospective test. Training selection preceded separate 2016–2020 validation and 2021-onward evaluation. Three cost scenarios and an extra trading-day delay were evaluated without parameter tuning. These are long/cash adaptations of ideas discussed by [Faber](https://mebfaber.com/2017/12/13/episode-86-quantitative-approach-tactical-asset-allocation/) and [Moskowitz, Ooi and Pedersen](https://w4.stern.nyu.edu/facdir/lpederse/papers/TimeSeriesMomentum.pdf), not replications of the papers' portfolios or return conventions.

Several longer-horizon rules produced positive results after the declared costs, including under the higher-cost and delay sensitivities. They trailed buy-and-hold in the later evaluation windows. The training-selected monthly rule also had a slightly worse later drawdown than that benchmark. Positive historical profit therefore did not establish excess return or reliable risk reduction. The selection diagnostic remained below its confidence threshold. At least **nine distinct non-cash rules**, including benchmarks, have now been examined across the research sequence; idle rules and unsuccessful experiments were retained. The reported trial-count adjustment is a lower-bound diagnostic, with dispersion estimated only from comparable daily training series, not a complete model of all researcher choices or serial dependence.

The longer tests use source OHLC price returns, without adjusted-close mixing or dividend cash flows: verified payment dates were unavailable and no settlement instant was invented. Cash yield and taxes are excluded; costs are sensitivity assumptions. A constant T+1 settlement policy is a research convention, not a reconstruction of historical settlement rules. Final open positions are marked, not reported as realized round trips. Dollar results at one-share size are reported privately; a large cash balance must not make percentage drawdown look like proof of low strategy risk. Stored historical revisions still do not provide immutable point-in-time data.

Two performance results matched the MCP and SDK paths. An additional **55 tests in four files passed**, covering the portfolio engine, its stepper, research-protocol diagnostics and the NYSE calendar. The existing paper account was inspected without new economic events. The regular session was closed; these follow-ups are historical simulations, not new forward paper fills. The three confirmed bugs above remain unfixed. The finding inventory now contains those three bugs, **four** data/model interpretation entries and **fourteen** usability entries; an earlier private summary incorrectly counted five data/model entries.

## Broader ticker research after scope clarification — 2026-11-02

SPY was specified by the original pilot attachment; it was not selected by a comparative company screen. The available provider discovery exposes company reference metadata, not a financial-statement or earnings-calendar service. Reference market caps can be weeks old and were not used as current valuation inputs. Four preliminary company checks used issuer disclosures and SEC filings separately; this does not complete valuation or due diligence for the full universe. A useful capability guide should make this boundary obvious rather than letting an agent equate a company profile with fundamental analysis. This is a research-coverage limitation, not an additional confirmed library bug.

Current flow and previous-session technicals retain their different observation clocks. Classified option premium is not known investor intent, and a large mid/unknown-side event does not establish directional buying. The off-exchange sample was the largest twenty prints across the population, with the disclosed fifteen-minute delay; absence from that sample is not zero activity, and quote side alone does not prove accumulation or distribution. The screen is a watchlist, not a tested multi-factor trading strategy. No new excess-return claim or candidate trade follows from ranking highly. The cumulative staging data-request allowance reached its declared limit; it was not reset. No calculation source, public contract or generated evidence changed.
